FYNDO — Production Website, SEO & PWA Integration

ROLE

Act as a senior product designer, UX architect, brand designer, SEO strategist and full-stack web developer.

You are building the official public website for FYNDO, a hyperlocal skilled-worker and local-services marketplace.

I have provided two important source materials:

FYNDO Pitch Deck — this is the primary source of truth for FYNDO's product positioning, problem, solution, target users, categories, workflows, trust model and roadmap.

17. MOBILE LOGIN EXPERIENCE

The existing FYNDO application uses phone-number-based login.

Preserve this approach.

The user should not have to type their phone number every time they launch the installed web app.

Implement a safe persistence strategy for the phone number.

Requirement

After the user successfully enters their mobile number:

Remember the phone number locally on the device.

Pre-populate it the next time the login screen is opened.

Provide an option to change the number.

Never expose the number in the URL.

Never store OTPs in local storage.

Never store authentication secrets insecurely.

Use appropriate browser storage mechanisms and secure authentication/session handling.

Example UX:

Mobile Number

98765 43210

[ Continue ]

Small option:

Use a different number

18. IMPORTANT SECURITY RULE

Do NOT interpret "cache the mobile number" as storing authentication credentials.

The application may remember the user's phone number for convenience, but:

OTPs must never be persisted.

Passwords, if any are introduced later, must never be stored in plain browser storage.

Authentication/session tokens must follow secure best practices.

Do not expose personal information in URLs.

Do not expose phone numbers through public page metadata.

Follow privacy-by-design principles.
